# PBFT 移植：任务表快照（M2 阶段收尾）

**这是一份快照，不是一份活文档。** 它记录某一次工作会话结束时任务表里的全部条目。

## 为什么要有这个文件

`docs/design/pbft-port-design.md` 里有 28 处引用形如 `#13`、`#24` 的票号。**那些票号指向的原始任务表从来不在这棵仓库里**（它由当时的协作工具持有，会话结束即消失），所以：

- 在这份文件存在之前，那 28 处引用**对任何读仓库的人都解析不了**——从写下的那一刻起就这样；
- 写这份文件不会让它们变得"将来也可查"，只会让它们**现在可查**；
- 票号**会被回收**：删掉一张票，下一张新建的票会拿到同一个号。所以 `#N` 永远是个弱标识，**标题才是强标识**。下面每条都带完整标题，就是为此。

**正确的用法：按标题找，别按票号找。** 票号只在"你已经有这份快照、正拿它核对文档"时有用。

## 快照边界

- **快照时刻**：任务表在 `18c8c6697` 那一刻的状态（该提交是 `fix(pbft-devnet): wire the cleanup criterion into gate.sh's exit paths`）
- 任务状态：28 条，全部 `completed`，0 条进行中，0 条待办
- **此后的任何新票都不在这份文件里。** 它是一张照片，不是一面镜子——写完就不动。文件自身被提交进来的那个提交，比上面那个号晚，两者的差就是"导出这个动作"本身。

## 与文档的对应关系

`pbft-port-design.md` 里用的是**双号登记**（`R21 / #24` 这种形式）：`R` 号属于那份文档，`#` 号属于这张表。两个坐标系指同一件事。

**如果两者冲突，以标题为准**——因为标题是唯一没有回收风险的标识。

## 一条不能省略的说明

**"全部 completed" 不等于"全部已修"。** 这张表混着三种东西：

- **改了代码并验证过的**（如 `#9`、`#13`、`#17`、`#24`）；
- **只改文档/注释的**（如 `#12`、`#22`、`#26`、`#28`）；
- **记录为债务、明确不修的**（如 `#11` 的 InfluxDB 凭据、`#21` 的忽略而非治理）。

要判断某一条到底做了什么，**看提交，不要看状态列**——`completed` 描述的是"这张票关掉了"，不是"这件事修好了"。
